# Phase 5 — UI Design Contract

> Visual and interaction contract for the Cohesive UI/UX Refresh. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Mobile-only (D-08), Vietnamese-first (D-01), token-driven on Ant Design 5 (D-06). No new packages, no state-shape changes (UX-05).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Ant Design 5.16.1 token system — shadcn deliberately NOT used; D-06 locks antd `ConfigProvider` tokens, research anti-patterns forbid a new styling lib) |
| Preset | not applicable |
| Component library | Ant Design 5.16.1 wrapped by `src/Components/` primitives (Card, Button, Typography, Tag, List, Stack, Empty, Spin, Result, Alert, Popconfirm, Popover, Message) |
| Icon library | `@ant-design/icons` (already in tree) |
| Font | Ant Design default system stack (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, ...`); do not introduce a custom font this phase |

**Token source of truth:** A single `src/theme/tokens.ts` (plain TS constants) feeding `buildAppTheme()` → antd `ThemeConfig` (`token` + `components` + `algorithm: [defaultAlgorithm, compactAlgorithm]`), consumed at the root by `ConfigProvider` in `src/App.tsx` and at render by `src/Components/` primitives via `useTheme` (`theme.useToken`). Module location is planner discretion (research recommends `src/theme/`). Keep craco Less vars (`@primary-color`, `@primary-fade`, `@text-color`) in sync with `tokens.ts`; JS tokens are authoritative (Pitfall 4).

## Spacing Scale

Declared values (must be multiples of 4). Mobile density is delivered by antd `compactAlgorithm` deriving padding from seed tokens — do NOT hand-tune per-component padding (research anti-pattern).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tag spacing, inline chip padding |
| sm | 8px | Compact spacing inside a card row, gap between metadata lines |
| md | 16px | Default gap between list rows, card inner padding, form field spacing |
| lg | 24px | Section padding, dashboard decision-group separation |
| xl | 32px | Major layout gaps between screen sections |
| 2xl | 48px | Reserved — large empty-state vertical centering |
| 3xl | 64px | Reserved — top/bottom page breathing room above floating controls |

Exceptions: **Tap targets — interactive controls (buttons, list-row tap affordances, COD include toggles, reveal triggers) must have a minimum 44px effective tap height** even when visual density is high. Drive via `controlHeight` token; keep `controlHeight >= 44` so `compactAlgorithm` density never produces sub-44px taps (D-09: dense but tappable).

## Typography

Replaces the current global `fontSize: 18` (the prime overflow cause, D-04) with a deliberate scale. Base font reduced to 14px; exactly 4 sizes, exactly 2 weights. Exact step values are planner discretion within this declared scale (Assumption A1).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 (regular) | 1.4 | Secondary metadata, captions, tag text, helper/timestamp lines on card rows |
| Body | 14px | 400 (regular) | 1.5 | Default text, list-row primary content, form values, button labels |
| Heading | 18px | 600 (semibold) | 1.3 | Screen titles, dashboard decision-group headers, section headers |
| Display | 24px | 600 (semibold) | 1.2 | Dashboard key metric numbers (COD total, order counts) |

Weights: exactly two — regular (400) and semibold (600). No light, no bold-900. Long fields (names, addresses, notes, shipping codes) stay at Body/Label size and use truncate-with-reveal (see Interaction Contract), never a larger size or wrap.

## Color

Palette folds in the existing `craco` Less `@primary-color`, the inline `App.tsx` tokens, and `COLORS`/`AppShadow` constants. 60/30/10 split tuned for a dense operations tool, not a marketing surface.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | App background, list/card row surfaces, form backgrounds |
| Secondary (30%) | `#f5f5f5` / border `#d9d9d9` | Card edges, dividers, status-tray surface, nav/floating-control chrome, row separators |
| Accent (10%) | `#f58220` (primary orange; fade `#ffefe0`) | Reserved — see list below |
| Destructive | `#990505` | Reserved — destructive/irreversible actions and "returned"/blacklist status only |

Accent reserved for: **primary CTA buttons (Tạo đơn / Áp dụng COD), the active/selected state of COD row inclusion, the selected tab/segment indicator, and the single most important "needs action" emphasis on the dashboard.** Never apply orange accent to all interactive elements, all tags, or decorative borders. Links use `#3d4195` (not the accent). Status semantics keep their existing domain colors from `COLORS` (shipped `#2aa345`, returned `#990505`, waiting `#f79a72`, pay-COD `#7B3F00`) — these are status encodings, not part of the 10% accent budget.

Shadows: `tokens.shadow.card = "0 0 15px 0 rgb(34 41 47 / 5%)"`, `tokens.shadow.notification = "0 5px 25px rgb(34 41 47 / 10%)"` (migrated from `AppShadow`). Replace the hard-coded `borderRadius: 10` in `Card.tsx` with the radius token.

## Interaction Contract

Mobile-only (D-08). These interaction rules are binding for every in-scope surface (dashboard, customer list, order list, order item/actions, order create, COD payment/review).

| Concern | Contract |
|---------|----------|
| Dense lists | Render as antd `List` card rows (`renderItem` → stacked single-height card), NOT desktop tables squeezed onto a phone (D-09). |
| Long-field overflow | Truncate-with-reveal, single-height rows (D-05). Use a **tap-triggered `Popover`** for inline fields (name/address/shipping code) and `Typography.Paragraph ellipsis={{ expandable, symbol: "xem thêm" }}` for long notes. **Do NOT use hover `tooltip`** — unreliable on touch (Pitfall 3). One mechanism used consistently across all screens. |
| Workflow states (UX-03) | Loading → `Spin`; Empty → `Empty` with Vietnamese `description`; Error → `Result status="error"` or `Alert type="error"`; Success → quiet `Message` (no persistent banner); Confirmation → `Popconfirm`. |
| Success/warning convention | Quiet success (transient `Message`), persistent warnings only when the operator must act (carried from Phase 4). |
| Dashboard (UX-04) | Group metrics by the decision they inform (needs-action-today, COD-to-reconcile, shipping-pending), reading derived values from existing `selectDashboardReadModel` — do not recompute in the view (UX-05). |
| Behavior preservation (UX-05) | Re-skin only. Keep every selector wiring (`selectOrderListReadModel`, `selectDashboardReadModel`), URL query sync (`OrderListQueryHelper`), and `useOrder`/Trello handler calls intact. No state-shape, enum-key, or selector changes for a visual edit. |

## Copywriting Contract

All operator-facing text MUST be Vietnamese (D-01). Strings stay inline in components — no i18n framework (D-03). Match terms already used in the ~95 Vietnamese files (e.g. "Thống kê", "Tổng tiền", "Tổng tiền COD"). Below are binding labels; exact domain wording confirmed against existing files during planning (A5).

| Element | Copy |
|---------|------|
| Primary CTA (order create) | `Tạo đơn` |
| Primary CTA (COD apply) | `Áp dụng COD` |
| Empty state heading | `Không có dữ liệu` |
| Empty state body — order list | `Không có đơn hàng` (+ next step: `Tạo đơn` button) |
| Empty state body — COD bucket | `Không có dòng nào trong nhóm này` |
| Error state | `Đã xảy ra lỗi` + actionable next step (e.g. `Thử lại`) — never a raw English stack message |
| Loading | `Đang tải...` |
| Truncate reveal trigger | `xem thêm` |

**Mandatory English→Vietnamese sweep (D-01/D-02).** Restore Vietnamese on all Phase 4-touched surfaces. COD bucket display labels in `OrderCodPaymentReview.widget.tsx` (keys unchanged, only display strings — Assumption A2):

| Key (unchanged) | English (remove) | Vietnamese (apply) |
|-----------------|------------------|--------------------|
| matched | Matched | `Đã khớp` |
| unmatched | Unmatched | `Chưa khớp` |
| duplicate | Duplicate | `Trùng` |
| amount-mismatch | Amount mismatch | `Lệch số tiền` |
| already-paid | Already paid | `Đã thanh toán` |
| (status) | Needs review | `Cần kiểm tra` |
| (label) | Payment row / Row {n} | `Dòng {n}` |
| (placeholder) | Manual resolve | (Vietnamese equivalent confirmed in planning) |
| (action) | Include | `Bao gồm` |
| (action) | Apply confirmed COD rows | `Áp dụng các dòng COD đã xác nhận` |
| (empty) | No rows in this bucket. | `Không có dòng nào trong nhóm này` |

Also sweep `OrderList.screen.tsx` option arrays (`COD_OPTIONS`, `SHIPPING_OPTIONS`, `SORT_OPTIONS` — e.g. "All COD", "Paid", "Newest") and any Empty/placeholder English text (Pitfall 5). Confirm no Latin-only operator-facing literal remains after the sweep.

**Destructive / irreversible confirmations** (use `Popconfirm`, Vietnamese):

| Action | Confirmation approach |
|--------|-----------------------|
| Apply confirmed COD rows | `Popconfirm`: confirm before applying COD payment to selected orders (irreversible state transition) |
| Mark order returned / refund | `Popconfirm` before the status transition |
| Restore from backup (if surfaced) | `Popconfirm` — overwrites current state |
