# Phase 04 Plan 01: Selector-Backed Operational Read Models

## Phase Goal

**As a** cassette store operator, **I want to** see dashboard and list totals computed consistently, **so that** search, COD, and operational utilities can build on trustworthy derived data.

<objective>
Extract tested order/customer/dashboard read models and wire the first visible consumers to them, preserving existing dashboard/list behavior while creating the foundation for COD import, URL-backed list filters, and status tray counts.
</objective>

<context>
Phase 4 decisions D-01, D-03, and D-04 require selector-backed read models. Current source facts: `DashboardScreen` and `OrderListScreen` contain inline reductions; `useOrder.ts` still exposes dashboard-style `getTotal*` helpers; `OrderReducer.ts` already imports `createSelector` and exposes small selectors. Keep local Redux/IndexedDB as the source of truth and do not introduce persisted UI state in this plan.
</context>
