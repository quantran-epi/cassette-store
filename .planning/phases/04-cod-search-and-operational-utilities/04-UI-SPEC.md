# Phase 04 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-phase, verified against Phase 4 CONTEXT.md and RESEARCH.md.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Ant Design 5 through existing local wrappers in `src/Components/` |
| Icon library | `@ant-design/icons` |
| Font | Existing app stack: Ant Design token `fontSize: 18`, browser system font for body, Kanit only where already used in app shell headings |

**Design intent:** Phase 4 surfaces are internal operations tools. They should be dense, calm, scannable, and action-oriented. Do not create marketing-style cards, large hero sections, decorative gradients, or a broad visual redesign. Phase 5 owns full UI/UX refresh.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/text gaps inside tags, compact row metadata |
| sm | 8px | Button groups, filter chips, review-row controls |
| md | 16px | Form groups, review bucket spacing, tray padding |
| lg | 24px | Modal/drawer section spacing, top-level screen groups |
| xl | 32px | Rare separation between major workflow stages |

Exceptions: existing brownfield values such as `5px`, `7px`, and Ant Design defaults may remain in untouched surfaces. New Phase 4 components should use the scale above unless matching an adjacent existing widget requires a one-off value.

## Component Contracts

### COD Import and Review

- Entry point should be on the COD payment screen near the existing add-cycle action.
- File selection uses Ant Design Upload or equivalent file input with upload prevented; parsing happens locally.
- The review screen must show these buckets as visible sections or tabs: `Matched`, `Unmatched`, `Duplicate`, `Amount mismatch`, `Already paid`.
- Each bucket row must show at minimum: file row number, shipping code, imported COD amount, imported shipping fee when present, matched order/customer when present, current app COD amount, and include/exclude/manual resolve state.
- The primary apply button remains disabled until there is at least one included confirmed row and no included unresolved rows.
- Manual column mapping must show detected columns and let the operator map shipping code, COD amount, shipping fee, status/date where available.
- Manual row resolution must not require leaving the COD review flow.

### Order List Search, Filters, and Sort

- Search and filter controls should fit above the order list in a compact filter band, not in a separate landing page.
- First-class controls: search, status, COD state, shipping-code state, date range, sort, and pagination/page state.
- Active filters must be visible after refresh because URL query params are the source of list view state.
- Summary chips must reflect filtered results: order count, expected cash amount, expected COD amount, and relevant status counts.
- Empty state must distinguish no orders at all from no orders matching filters.

### State-Aware Row Actions

- Each order row should promote one primary next action based on order state when a clear next action exists.
- Secondary actions may stay grouped in a menu, but groups must be understandable: delivery state, order details, customer/details, attachments/refund/delete.
- Dangerous actions such as delete, refuse-to-receive, returned, and irreversible COD-paid changes require confirmation.
- Disabled actions need a visible reason through tooltip or clear absence; do not leave important actions mysteriously disabled.

### Operational Status Tray

- Tray lives near the existing floating controls and must not overlap the bottom navigation or COD/order action controls on mobile.
- Tray shows counts or compact lines for Trello sync failures, backup status, done-order refresh status, and COD import/apply issues.
- Tray may navigate to filtered order list or COD review and may trigger safe checks: backup now and refresh done orders.
- Tray must not clear Trello failures, mark manual resolved, or apply COD rows directly. Those actions stay on local row/screen details.
- Quiet success is allowed: do not persist large success banners for all-good states.

## Responsive Contract

| Viewport | Contract |
|----------|----------|
| Mobile narrow | One-column flow; filter groups wrap; COD review buckets use stacked rows or tabs; primary CTA stays reachable; bottom nav remains unobstructed. |
| Tablet | Two-column review layout is allowed only if rows remain readable; tray stays compact. |
| Desktop | COD review may use table layout with fixed action column; order list filter band can use multiple inline controls. |

Rules:
- Fixed-format controls such as icon buttons, filter chips, status tags, and tray rows need stable dimensions or wrapping so text does not overlap.
- Cards should be reserved for individual repeated rows or genuinely framed tools. Do not put cards inside cards.
- Use icons from `@ant-design/icons` for file import, mapping, apply, warning, retry, status, filter, and sort actions where available.

## Workflow States

| Workflow | Loading | Empty | Error | Success | Review/Pending |
|----------|---------|-------|-------|---------|----------------|
| COD import | Parsing file indicator | No COD file imported | Could not read file / unknown format | Parsed file summary | Buckets with unresolved rows |
| COD apply | Applying confirmed rows | No confirmed rows selected | Apply failed, no unresolved rows mutated silently | Cycle created and rows marked paid | Included unresolved rows block apply |
| Order list | Optional filter debounce/loading if needed | No orders or no filtered matches | Query parse fallback resets invalid params | Results and summary chips update | Active filters visible |
| Status tray | Backup/done refresh loading | Hidden or compact idle state | Actionable issue line | Compact timestamp/count | Click through to local resolution |
