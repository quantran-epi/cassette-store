# Phase 04 Plan 03: URL-Backed Order Search, Filters, and Sort

## Phase Goal

**As a** cassette store operator, **I want to** search, filter, sort, and page the order list without losing context, **so that** I can move between details, COD work, and operational alerts without rebuilding my list view.

<objective>
Move order list view state into URL query params, expose all Phase 4 filter/sort dimensions as first-class compact controls, and wire the list to selector-backed read models so refresh, browser back, and return-to-list preserve operator context.
</objective>

<context>
Plan 04-01 creates selector-backed order list read models. The current `OrderList.screen.tsx` keeps search, status filters, COD filter, and pagination in component-local state and only searches order name/shipping code. Phase 4 decisions D-02 through D-04 require broad order/customer search plus URL-backed controls for every daily list dimension.
</context>
