# Phase 04 Plan 04: State-Aware Actions and Operational Status Tray

## Phase Goal

**As a** cassette store operator, **I want to** see the next useful action on each order and an app-wide status tray for problems, **so that** daily follow-up work is faster without moving destructive resolution into global controls.

<objective>
Extract the order row action model into a state-aware surface and replace the ad hoc backup/done notification box with a compact operational tray that surfaces Trello sync failures, backup status, done-order refresh status, and COD import/apply issues while routing the operator to the right local resolution surface.
</objective>

<context>
Existing `OrderItem.widget.tsx` has two dense dropdowns with mixed delivery, customer, attachment, refund, and delete actions. Existing `MasterPage.AppNoti` displays backup and done refresh status near the FloatButton group. Phase 4 decisions D-12 through D-15 require clearer contextual row actions and an app-wide tray that can navigate or trigger safe checks but must not clear sync failures or apply COD rows directly.
</context>

<threat_model>
Threat T-04-02 is that a global status surface performs destructive or context-heavy actions from the wrong place. This plan mitigates it by keeping tray actions to navigation, backup-now, and refresh-done-orders; Trello failure clear/manual-resolved actions remain in `OrderSyncStatusWidget`, and COD apply remains in the COD review screen.
</threat_model>
