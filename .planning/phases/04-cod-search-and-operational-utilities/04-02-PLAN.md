# Phase 04 Plan 02: COD Excel Import, Review, and Apply

## Phase Goal

**As a** cassette store operator, **I want to** import a COD settlement spreadsheet, review matches, and apply confirmed rows, **so that** paid COD state and COD cycles can be updated without manually hunting through every order.

<objective>
Replace the manual-only COD cycle creation path with a staged Excel import workflow that parses known COD exports, falls back to manual column mapping when formats change, buckets rows for review, and applies only confirmed included matches to local order/COD state.
</objective>

<context>
Phase 4 decisions D-05 through D-11 make COD settlement import the primary workflow for COD cycle creation. Existing `OrderCodPaymentCreate.widget.tsx` manually selects payment and debit-fee orders, while `useOrder.addPaymentOrderCycle` appends a `CodPaymentCycle` and marks selected payment orders as paid COD. Preserve that domain behavior, but add deterministic parse/review/apply helpers and UI so Excel data is never applied silently.
</context>

<threat_model>
Threat T-04-01 is that imported spreadsheet rows incorrectly mark orders as paid COD. This plan mitigates it by keeping parse/review state local, requiring review buckets before apply, disabling apply when included unresolved rows exist, testing duplicate/amount/already-paid cases, and mutating Redux only from a confirmed apply payload.
</threat_model>
